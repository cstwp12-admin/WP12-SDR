# Change log

All changes to the WP12 Site Photo Report app. The version in use is shown in the app under **Setup** (bottom panel).

| Version | Date | Changes |
|---|---|---|
| 1.2.1 | 10 Oct 2026 | QC testing added as its own category: 48 contract QC tests (not in the BQ) from the Schedule of Testing, marked **QC** in the list, captions and reports, e.g. *Cube test – G40 · QC*. The BQ testing category is renamed **QA testing & inspection**. A photo can now have **more than one activity** (tap each in the list, then Done); bulk tagging and *Copy previous* carry all of them. Optional team register guide (TEAM_REGISTER.md) and its script (Code.gs) added to the repository; the script itself is unchanged. |
| 1.2 | 09 Oct 2026 | Pilot version. ROADMAP.md added. RFI photo record: sign-off blocks changed to **Prepared by (WPC)**, **Checked by (CST)** and **Acknowledged by (SOR)** (BM: *Disediakan oleh*, *Disemak oleh*, *Diperakui oleh*). Result heading reads **Inspection (by CST)**. The RFI record footer reads "Generated by" so it does not clash with the Prepared by block. README updated to match. |
| 1.1 | 09 Oct 2026 | First version published on GitHub. RFI photo record added: one PDF per RFI no., following the JKR Sabah RFI form, with result tick boxes, comments, sign-off blocks and photos. Register log added (Reports, RFIs, Photos; CSV export; import other users' logs; optional Google Sheet team register). Activity list extended to 120 items, including hydromulching (BQ 7.5.3), rock drilling & blasting, proof rolling, joint dipping and cube tests. Users can add activities in Setup. Zones Z1–Z4 set. Warning when a photo's chainage is outside the zone in the header. `setup.json` loads the project setup on every phone automatically. |
| 1.0 | 09 Oct 2026 | First working version (tested internally, not published on GitHub): photo tagging by activity (BQ ref), structure, chainage, side, element, RFI no. and remarks. Chainage from GPS using the WP12 centreline. PDF report with 4 photos per page, captioned photos, WhatsApp summary text, ZIP archive. Captions in English, BM or both. Works offline. |

## How a revision is recorded

1. The version number in the app (`index.html`) goes up for every change: a third number for small additions or fixes between planned releases (1.2 → 1.2.1), the second number for a planned release in the roadmap (1.2 → 1.3), and the first number for a major change (2.0).
2. A row is added at the top of the table above.
3. The GitHub commit message starts with the version, e.g. `v1.2 – RFI record: Inspected by (CST)`.
